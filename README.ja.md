# Redmine Out of Band Auth

日本語 | [English](README.md)

**Redmine 7.0 標準の二要素認証（2FA）に、メール確認コード方式を追加するプラグイン**です。
このブランチはプラグイン **2.0.0** で、自動テストの対象環境は Redmine **7.0.3**、
Rails **8.1.4**、Ruby **4.0.9**、SQLite です。旧バージョンの Redmine では旧版プラグインを使用してください。
再現可能なテスト手順と対象範囲は「[テスト](#テスト)」を参照してください。

## 導入前の確認

- メール認証を有効にする前に、Redmine のメール送信を設定し、実際に受信できることを確認します。
- 本番環境は HTTPS で運用します。利用者が Redmine に登録した**主メールアドレス**でメールを受信できる必要があります。
- 移行や二要素認証の必須化の前に、復元を確認済みのデータベースバックアップと管理者による復旧手段を用意します。
- 1 ユーザーで有効にできる二要素認証は、メール方式**または**認証アプリ方式（TOTP）のどちらかです。
  既存の TOTP 設定は維持されます。メール方式で TOTP を迂回することはできません。
  方式を変更する場合は、Redmine の通常の操作で現在の方式を無効化してから設定します。

## インストール

Redmine 配下の `plugins/redmine_out_of_band_auth` に、このブランチを配置します。
旧版と新版のプラグインを別々のディレクトリに置いて同時に読み込ませないでください。

```sh
cd /path/to/redmine
git clone --branch redmine-7-native-twofa \
  https://github.com/nepnyan3/redmine_out_of_band_auth.git \
  plugins/redmine_out_of_band_auth
bundle install
RAILS_ENV=production bundle exec rake redmine:plugins:migrate NAME=redmine_out_of_band_auth
RAILS_ENV=production bundle exec rake assets:precompile
```

アプリケーションの全プロセスを再起動します。**管理 > プラグイン**に
**Redmine Out of Band Authentication plugin 2.0.0** が表示されることを確認してください。
Rails の秘密鍵は、すべてのアプリケーションインスタンスで同じ値を継続して使用します。
鍵を変更すると、発行済みで未使用の確認コードが無効になります。

## 設定手順

以下は Redmine 7.0.3 の画面構成に沿った手順です。

### 1. メール送信を確認する

[Redmine のメール設定ガイド](https://www.redmine.org/projects/redmine/wiki/EmailConfiguration)に従い、
利用環境の `config/configuration.yml` にメール配送設定を記載します。変更後は Redmine を再起動します。
**管理 > 設定 > メール通知**で送信元アドレスを確認し、**テストメールを送信**を実行して、
実際にメールが届くことを確認してください。
プラグインは Redmine のメール設定を使用し、独自の SMTP 設定画面はありません。
対象ユーザーへの配送を確認するまでは、メール二要素認証を必須にしないでください。

### 2. 二要素認証を利用可能にする

**管理 > 設定 > 認証**を開き、**二要素認証**を **任意**にして**保存**します。
まず任意設定で登録とログインを確認し、メール配送と復旧手順を検証してから、必要に応じて
組織の方針に合わせて必須化してください。管理者だけに二要素認証を必須とする設定もあります。

### 3. 自分のアカウントでメール認証を有効にする

**個人設定**を開き、主メールアドレスが正しいことを確認します。
**二要素認証**欄の**メール認証を有効にする**を選択してください。
途中でパスワードの再確認を求められる場合があります。
欄が表示されない場合は、サイト全体の二要素認証設定とプラグインの読み込みを確認します。
別方式がすでに有効な場合は、Redmine の通常の認証手順でその方式を無効化してから変更してください。

### 4. 確認コードを入力して登録を完了する

主メールアドレスに届いた **6 桁**のコードを入力し、フォームを送信します。
コードの有効期限は **2 分**です。この確認が完了して初めてメール認証が有効になります。
再送には **30 秒**の待ち時間があり、新しいコードを発行すると前のコードは使えなくなります。

**個人設定**に戻り、**メール認証コード**が有効になっていることを確認します。
Redmine 標準のバックアップコードを生成し、メールボックスやこのリポジトリとは別の安全な場所に保管してください。
パスワード、有効な確認コード、バックアップコードが写った画像を公開しないでください。

### 5. 次回のログインを確認する

いったんログアウトして、ユーザー名とパスワードでログインします。
二要素認証の画面が表示されたら、そのとき新しく届いたメールのコードを入力してください。
パスワード認証だけではログインは完了しません。
必須設定を検証するときは、復旧のため別の管理者セッションを確保しておきます。

## 旧プラグインからの移行

1. **データベース、添付ファイル、Redmine の設定・秘密鍵、既存プラグイン**をバックアップし、復元を確認します。
2. [Redmine のアップグレードガイド](https://www.redmine.org/projects/redmine/wiki/RedmineUpgrade)に従って、
   検証用の複製環境に新しい Redmine を用意します。**新環境の起動やマイグレーションより前に**、
   同じディレクトリの旧プラグインをこのブランチへ置き換え、下記の移行修正を含めてください。
3. 新しい Redmine のルートで、依存関係の導入、本体・プラグインの移行を実行します。

   ```sh
   bundle install
   RAILS_ENV=production bundle exec rake db:migrate
   RAILS_ENV=production bundle exec rake redmine:plugins:migrate NAME=redmine_out_of_band_auth
   RAILS_ENV=production bundle exec rake assets:precompile
   ```

   アップグレード完了後、アプリケーションの全プロセスを再起動します。
4. メール配送、サイト全体の二要素認証設定、移行対象ユーザーのログインを確認します。
   確認と復旧手順の検証が終わるまでは、バックアップを保持してください。

プラグインのマイグレーションは、次のように設定を移行します。

| 移行前 | 移行後 |
| --- | --- |
| 旧 `enabled_out_of_band_auth` が有効で、標準の二要素認証方式が未設定 | メール方式が有効になる。利用者による再登録は不要 |
| 旧方式が有効で、標準の TOTP なども設定済み | 既存の標準方式を維持 |
| 旧方式が無効 | メール方式を自動では有効にしない |
| サイト全体の二要素認証が無効で、メール方式に移行したユーザーが存在 | サイト全体の二要素認証を**任意**に変更 |

メール方式へ移行したユーザーの既存ログインセッションと自動ログイントークンは、Redmine により失効します。
再ログイン時は、**新しく発行されたメールコード**を使用します。旧コードは破棄され、旧平文コード列も削除されます。
旧チェックボックス、独自ログイン URL、暗号化タスクの上書きは廃止されています。
新方式は鍵付きダイジェストを保存するため、メールコードのために旧 `database_cipher_key` を設定する必要はありません。
ただし、SCM や LDAP の認証情報など、ほかの Redmine データの暗号化に使用している鍵は保持してください。

**このマイグレーションは元に戻せません。** `VERSION=0` や旧プラグインの上書きでダウングレードしないでください。
戻す場合は、移行前のデータベース、設定、プラグイン、対応する Redmine 本体を一式で復元します。

### 実際の旧版からの移行検証結果

**2026-11-11**、実際の **Redmine 3.4.13 / プラグイン 1.0.0** 上で架空ユーザーのメール認証を完了し、
その **SQLite データベース**を **Redmine 7.0.3 / プラグイン 2.0.0（今回の移行修正を含む）**へ移しました。
ユーザー ID、ログイン名、パスワードハッシュ、主メールアドレスを維持し、
同じパスワードと移行後に新しく発行されたメールコードで、**再登録なしに認証できることを確認**しました。

旧環境の **11 チェック**、移行後の **28 チェック**、既存回帰テストの **20 tests / 144 assertions** が成功しました。
既存回帰テストの failures / errors / skips はすべて 0 です。
旧セッション・旧コードの失効、未登録ユーザーを自動登録しない動作、標準バックアップコードによるログインも確認しています。
正確なバージョン、固定イメージ、手順、制限は[移行検証レポート](docs/verification/redmine-7-migration.md)を参照してください。

本体とプラグインを**同じ rake プロセスで移行**すると、モデルの列情報が古いまま残り、
旧方式が有効なユーザーでも標準メール方式が未設定になる不具合を再現し、修正しました。
適用済みとして記録されたマイグレーションは、ファイルを置き換えるだけでは再実行されません。
旧対応版ですでに移行済みの場合は、本番データベースを手動で巻き戻さず、
バックアップを復元した複製環境で状態を確認して、復旧計画を立ててください。

この検証は、テスト用メール配送を捕捉する HTTP 統合テストです。ブラウザーの画面操作や本番 SMTP 配送を検証したものではありません。
ほかの旧 Redmine、MySQL、PostgreSQL、LDAP / SSO の全経路、本番固有データ・他プラグインとの組み合わせは未検証です。
本番反映前に、実環境のバックアップを使って検証してください。

## セキュリティとトラブルシューティング

- コードは `SecureRandom` で生成し、2 分で失効します。検証はデータベースの行ロック下で行い、
  成功したコードを再利用できないようにします。保存するのはユーザーに紐付いた鍵付き SHA-256 HMAC のみです。
- 1 回のコード発行で試行できるのは**合計 3 回**です。再送しても残り試行回数は戻りません。
  上限に達した場合は、有効期限が切れてからやり直してください。
- 送信は 1 ユーザーにつき 30 秒に 1 回です。待ち時間中は新たなメールを送りません。
  再送に成功すると前のコードは無効になります。Redmine 本体にもログイン待機セッションの制限があります。
- 二要素認証に成功するまで、ログイン済みセッションや自動ログイン Cookie は発行されません。
- 届かない場合は、主メールアドレス、迷惑メール、Redmine のメール設定、アプリケーションログ、
  メールサーバーの配送状況を確認してください。不具合報告に実際の認証情報やコードを含めないでください。
- コードが通らない場合は、最新メールのコード、有効期限、試行回数を確認してください。
- メールを受信できない場合は、事前に保存したバックアップコードを使うか、信頼できる管理者へ連絡し、
  本人確認のうえで Redmine 標準の二要素認証リセットを行ってください。
- REST API キーや、認証済みの自動ログインについては Redmine 標準の動作を維持します。
  API リクエストに対話式の二要素認証を追加するものではありません。
- メール方式の安全性と利用可否はメールボックスに依存します。独立した認証器が必要な場合は TOTP を使用してください。

## テスト

Docker があれば実行でき、ローカルの Ruby や SMTP 認証情報は不要です。
プラグインの checkout で次を実行します（POSIX シェル表記）。

```sh
docker build -t redmine-oob-test test/docker
docker run --rm --network none \
  --mount "type=bind,src=$PWD,dst=/usr/src/redmine/plugins/redmine_out_of_band_auth,readonly" \
  redmine-oob-test bash plugins/redmine_out_of_band_auth/test/run.sh
```

TLS 検査プロキシを使用する環境では、信頼する CA バンドルを
`--secret id=ca,src=/path/to/ca-bundle.pem` でビルドに渡します。証明書検証は無効にしません。
使い捨てコンテナで、旧データベース状態からの移行、eager loading、認証、TOTP との共存、
有効期限、再利用拒否、試行回数・再送制限、利用登録、バックアップコード、開発時のクラス再読み込みを確認します。
GitHub Actions も同じコマンドを実行します。外部 SMTP サービスへメールを送るテストではありません。

### 実際の旧データベースからの移行を再現する

上記の手順で `redmine-oob-test` をビルドします。
固定した旧プラグインのコミットを取り出すため、Git の全履歴を含む checkout を使用してください。

Windows PowerShell（今回、旧環境から移行後まで通して実行済み）:

```powershell
.\test\upgrade\run.ps1 -TestImage redmine-oob-test
```

Linux / Bash（GitHub Actions でも使用）:

```sh
TEST_IMAGE=redmine-oob-test bash test/upgrade/run.sh
```

固定した Redmine 公式イメージと架空ユーザーのみを使用し、旧版・新版ともに `--network none` で実行します。
本番データベースの読み取りや外部へのメール送信は行いません。
実行用コンテナは削除し、架空ユーザーの移行元 SQLite データベースと比較用 JSON は、表示された一時ディレクトリに保持します。

## アンインストール

プラグインを削除する**前に、メール方式を使用する全ユーザーの認証を Redmine 上で無効化**してください。
先に削除すると、存在しない二要素認証方式がユーザーに残り、ログインできなくなります。
データベースバックアップを保管してください。セキュリティ更新のマイグレーションを down で戻すことはできません。
